# Ubuntu20.04 ECS Node 定时脚本部署文档
> 系统：Ubuntu 20.04.6 LTS 阿里云 ECS  
> 项目目录：`/opt/elec-policy-opencode`  
> 入口脚本：`/opt/task.sh`（内部执行 `/root/.nvm/versions/node/v20.20.2/bin/node scripts/monthly-flow.mjs`）  
> 日志文件：`/opt/elec-policy-opencode/logs/{时间戳}.log`，每次执行独立一份（示例：`logs/2026-09-16_17-24-10.log`）  
> 执行逻辑：task.sh 统一封装 nvm 加载、PATH 注入、目录切换、日志落盘、退出码记录，内部调用的 Node 脚本再执行 OpenCode CLI 业务任务  
> 定时规则：**北京时间每天 22:00 执行 1 次**；生产模式仅在每月最后 3 个自然日执行业务，其余日期退出 0。月末最后一天的公告可能在早上 9 点后下发，因此安排在晚间执行。
> ⚠️重要提醒：cron 不会加载交互式 shell 环境变量。nvm 加载、node 绝对路径、PATH 注入均已封装在 `/opt/task.sh` 内，**无需再修改 `monthly-flow.mjs`**；cron 只需一行调用 task.sh。
> 

## 0. 前置准备
1. ECS 安全组入方向放行 **22 端口 (SSH)**
2. 获取服务器公网 IP
3. 本地终端登录服务器

```plain
ssh root@你的服务器公网IP
```

## 1. 服务器安装 Node.js 20 与 OpenCode CLI
```plain
# 安装nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 生效nvm环境
source ~/.bashrc


# 安装Node.js 20
nvm install 20
(国内下载太慢时用镜像)
NVM_NODEJS_ORG_MIRROR=https://npmmirror.com/mirrors/node nvm install 20
nvm use 20
nvm alias default 20

# 安装OpenCode CLI
curl -fsSL https://opencode.ai/install | bash 
(国内下载慢可用 npm 国内镜像全局安装)
npm config set registry https://registry.npmmirror.com
npm install -g opencode-ai

source ~/.bashrc

# 校验安装
node -v
npm -v
opencode --version
```

## 5. 配置 Cron 定时任务
定时任务，追加模式（推荐）

```plain
crontab -e
```

编辑器末尾追加下面一整行，保存退出

```plain
# 每天北京时间22点定时触发（服务器时区为 Asia/Shanghai）
0 22 * * * /bin/bash /opt/task.sh
```

> 将已有的 `0 9 * * *` 任务替换为上面的规则，不要保留两条任务。cron 按服务器时区调度，先用 `timedatectl` 核对时区；北京时间部署可执行 `sudo timedatectl set-timezone Asia/Shanghai`。
>
> 模型密钥：无需任何 API_KEY 环境变量，也不走 API 额度计费。按 §4 用智谱 GLM Coding Plan 订阅 Key 完成 `opencode auth login` 即可，`auth.json` 凭据文件对 cron 环境生效。
>

查看已配置定时任务

```plain
crontab -l
```

去看脚本实际运行输出

```plain
tail -n50 "$(ls -t /opt/elec-policy-opencode/logs/*.log | head -1)"
```


## 6. 生产环境部署与上传配置

生产服务器沿用 §1–§3 的安装步骤及目录结构，以运行定时任务的同一系统用户完成 §4 的 OpenCode 登录。上传地址和账号统一放在项目根目录 `upload.config.json`，不通过环境变量配置。

### 6.1 配置测试 / 生产上传目标

首次部署从示例复制（已有配置时直接编辑，不要覆盖原账号）：

```bash
cd /opt/elec-policy-opencode
cp upload.config.example.json upload.config.json
chmod 600 upload.config.json
```

配置示例（正式地址、账号、密码替换为实际值）：

```json
{
  "enabled": true,
  "environments": {
    "test": {
      "enabled": true,
      "base": "http://api-test.star-grid.com/Nevermore",
      "user": "测试环境账号",
      "password": "测试环境密码"
    },
    "production": {
      "enabled": true,
      "base": "https://正式环境域名/Nevermore",
      "user": "正式环境账号",
      "password": "正式环境密码"
    }
  }
}
```

根级 `enabled` 为上传总开关，默认 `false`；`environments` 中每个环境的 `enabled` 为独立开关，默认 `false`。

| 上传模式 | 根级 enabled | test.enabled | production.enabled |
| --- | --- | --- | --- |
| 仅下载、解析 | false | 任意 | 任意 |
| 仅测试环境 | true | true | false |
| 仅正式环境 | true | false | true |
| 测试和正式同时上传 | true | true | true |

未启用的环境不登录、不上传，可留空账密；总开关开启但没有启用任何环境时仍为「仅解析」。各环境的地址和账号填写在 `environments.test` 或 `environments.production` 对应字段中。未知字段会报错，不会静默忽略。

同一次任务只下载、解析一次，各启用环境使用自己的账号分别登录，各提交一次相同的电价数组。某环境失败仍继续处理另一环境；返回值 `environments.test` / `environments.production` 分别记录状态。只有所有启用环境都成功，整体才为「更新成功」；部分成功时整体为「上传失败」，报告须列明各环境实际结果。

### 6.2 切换生产运行模式

1. 在 `/opt/task.sh` 中移除或注释 `export FORCE_RUN=1`，生产定时恢复月末最后 3 天窗口。
2. 核对服务器时区为 `Asia/Shanghai`，按 §5 将 cron 改为 `0 22 * * * /bin/bash /opt/task.sh`。
3. 在 `upload.config.json` 填写实际正式环境地址和账号，按上表选择仅正式或双环境上传。
4. 需要窗口外手动验证时，临时将 task.sh 的 `FORCE_RUN` 设为 `1`，执行 `bash /opt/task.sh`，验证后移除。若根级上传开关已开启，这次测试会向所选环境实际入库。
5. 核对日志、`data/report/{目标月}/{MM-DD}.txt` 以及各启用环境的入库结果。

**已有 JSON 的补传**：flow 会跳过本轮开始前已有的终稿 JSON，因此增加正式目标、切换开关或某环境失败后，不能靠再次执行 flow 自动补传。应对已有终稿显式调用上传脚本，`jsonMap` 仅列出需要补传的文件，并只开启待补传环境，避免重复提交已经成功的环境。例如：

```bash
node .opencode/skills/upload/scripts/post.mjs 2026-11 '{"zhejiang":"data/json/2026-11/浙江.json"}'
```

补传完成后恢复预期的环境开关。
