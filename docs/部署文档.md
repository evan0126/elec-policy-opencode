# Ubuntu20.04 ECS Node 定时脚本部署文档
> 系统：Ubuntu 20.04.6 LTS 阿里云 ECS  
> 项目目录：`/opt/elec-policy-opencode`  
> 入口脚本：`/opt/task.sh`（内部执行 `/root/.nvm/versions/node/v20.20.2/bin/node scripts/monthly-flow.mjs`）  
> 日志文件：`/opt/elec-policy-opencode/logs/{时间戳}.log`，每次执行独立一份（示例：`logs/2026-09-16_17-24-10.log`）  
> 执行逻辑：task.sh 统一封装 nvm 加载、PATH 注入、目录切换、日志落盘、退出码记录，内部调用的 Node 脚本再执行 OpenCode CLI 业务任务  
> 定时规则：**每天早上 09:00 执行 1 次**  
> ⚠️重要提醒：cron 不会加载交互式 shell 环境变量。nvm 加载、node 绝对路径、PATH 注入均已封装在 `/opt/task.sh` 内，**无需再修改 `monthly-flow.mjs`**；cron 只需一行调用 task.sh。
> 

## 0. 前置准备
1. ECS 安全组入方向放行 **22 端口 (SSH)**
2. 获取服务器公网 IP
3. 本地终端登录服务器

```plain
ssh root@你的服务器公网IP
```

## 1. 服务器安装 Node.js 20 与 OpenCode CLI
```plain
# 安装nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 生效nvm环境
source ~/.bashrc


# 安装Node.js 20
nvm install 20
(国内下载太慢时用镜像)
NVM_NODEJS_ORG_MIRROR=https://npmmirror.com/mirrors/node nvm install 20
nvm use 20
nvm alias default 20

# 安装OpenCode CLI
curl -fsSL https://opencode.ai/install | bash 
(国内下载慢可用 npm 国内镜像全局安装)
npm config set registry https://registry.npmmirror.com
npm install -g opencode-ai

source ~/.bashrc

# 校验安装
node -v
npm -v
opencode --version
```


## 2. 本地上传项目到服务器
压缩打包后上传解压/阿里云网页/图形化工具都可以

> 目录规则：项目放 `/opt/elec-policy-opencode`，`task.sh` 放 `/opt/task.sh`（与项目目录同级，task.sh 内部会自动 cd 进项目目录）。  
> 打包时注意排除 `node_modules`、`.git`等不需要上传的文件  
>

## 3. 服务器项目初始化
```plain
# 进入项目根目录
cd /opt/elec-policy-opencode

# 安装项目依赖
npm install

# 创建日志文件夹（task.sh 每次也会自动 mkdir -p logs，此处提前创建便于核对）
mkdir -p logs

# 给脚本增加可执行权限
chmod +x /opt/task.sh
chmod +x scripts/monthly-flow.mjs

# 校验脚本文件存在
ls -la /opt/task.sh
ls -la scripts/
```

## 4. 手动测试脚本（必须手动跑通，再配置定时）
> 直接执行入口脚本即可，task.sh 内部已封装 nvm 加载、目录切换、日志落盘，和 cron 运行环境完全一致
> 

```plain
bash /opt/task.sh
```

查看日志确认执行无报错（每次执行生成一份时间戳命名的独立日志）

```plain
# 查看最新一次日志
cat "$(ls -t /opt/elec-policy-opencode/logs/*.log | head -1)"

# 查看历史日志列表
ls -lt /opt/elec-policy-opencode/logs/
```

> ✅只有手动执行完全正常，才往下配置 cron 定时任务。
>
> 模型选择：模型服务商以项目 `opencode.json` 配置为准（当前为**智谱 GLM Coding Plan 订阅方式**，如 `zhipuai-coding-plan/glm-5.3`），**不走 API 额度计费、无需配置 API_KEY 环境变量**，服务器上用订阅 Key 完成一次 opencode 登录即可：
>

```plain
# 1. 智谱开放平台（bigmodel.cn）订阅 GLM Coding Plan，在订阅页 / API Keys 页获取订阅专用 Key

# 2. SSH 终端执行，提供商列表选择 Coding Plan 对应项（Z.AI Coding Plan / 智谱 Coding Plan）
opencode auth login

# 3. 按提示粘贴第 1 步获取的订阅 Key

# 4. 核对登录状态
opencode auth list
```

> 凭据写入 `~/.local/share/opencode/auth.json`，文件方式落盘，cron 定时环境同样生效；注意保管不要外泄。
>

> ⚠️FORCE_RUN 开关：task.sh 当前默认 `export FORCE_RUN=1`，即**每次都跳过月末日期判断、强制完整执行业务任务**（适用于测试）。生产定时若只需每月末 3 天窗口自动执行，将该行注释掉即可；monthly-flow.mjs 自身会在非窗口日退出 0。
>

## 5. 配置 Cron 定时任务
定时任务，追加模式（推荐）

```plain
crontab -e
```

编辑器末尾追加下面一整行，保存退出

```plain
# 每天早上9点定时触发（nvm 加载、PATH、日志均已封装在 task.sh 内）
0 9 * * * /bin/bash /opt/task.sh
```

> 模型密钥：无需任何 API_KEY 环境变量，也不走 API 额度计费。按 §4 用智谱 GLM Coding Plan 订阅 Key 完成 `opencode auth login` 即可，`auth.json` 凭据文件对 cron 环境生效。
>

查看已配置定时任务

```plain
crontab -l
```

去看脚本实际运行输出

```plain
tail -n50 "$(ls -t /opt/elec-policy-opencode/logs/*.log | head -1)"
```


## 6. 运维排查命令
```plain
# 实时查看最新一份业务日志
tail -f "$(ls -t /opt/elec-policy-opencode/logs/*.log | head -1)"

# 查看历史日志列表（按时间倒序）
ls -lt /opt/elec-policy-opencode/logs/

# 查看cron系统调度日志，排查定时是否触发
grep CRON /var/log/syslog

# 模拟cron环境调试脚本，直接执行入口脚本（与定时任务行为完全一致）
bash /opt/task.sh

# 查看opencode路径
which opencode
```
